# POD-Bench 재설계 계획 (v2)

작성일: 2026-07-15

이 문서는 벤치마크를 왜 바꾸려 하는지, 무엇을 어떻게 바꾸는지, 바꾸면 뭐가
좋아지는지를 처음 보는 사람도 따라올 수 있게 정리한 것입니다. 계획의 논리에
빈틈이 없는지 검토하는 용도로 쓰입니다.

---

## 1. 배경: 이 벤치마크는 무엇을 측정하나

POD-Bench의 문제 하나는 이렇게 생겼습니다.

> **질문(쿼리)**: "오늘 저녁 회사 연말 갈라 파티에 가요. 뭘 입을까요?"
> (질문하는 가상 유저에게는 취향 프로필이 있음 — 예: 체크무늬를 좋아하고 솔리드를 싫어함)
>
> **선지 4개** (각각 실제 옷 이미지로 제시):
> - **A. 검정 체크무늬 롱스커트** → 상황에 맞고(TPO ✓), 취향에도 맞음(선호 ✓) → **정답**
> - **B. 검정 솔리드 롱스커트** → 상황에는 맞지만 취향이 아님
> - **C. 노란 체크무늬 롱스커트** → 취향이지만 상황에 안 맞음 (갈라에 노란색은 부적절)
> - **D. 노란 솔리드 롱스커트** → 상황에도 취향에도 안 맞음

즉 모델이 **"상황 판단(TPO)"과 "개인 취향(선호)"을 동시에 고려해서 옷을
추천할 수 있는가**를 측정합니다. 선지 4개는 항상 (TPO ○/×) × (선호 ○/×)의
2×2 조합입니다.

여기서 계속 쓰게 될 용어 두 개만 정리하면:

- **선호 축 (active axis)**: A·B를 가르는 속성. 위 예시에서는 무늬(체크 vs 솔리드).
  옷의 속성은 세 가지 — 옷 종류(garment), 색(color), 무늬(pattern) — 이고
  그중 하나가 선호 축이 됩니다.
- **위반 축 (violation axis)**: C·D를 "상황에 안 맞게" 만드는 속성. 위 예시에서는
  색(노랑). 역시 세 속성 중 하나입니다.

나머지 속성(위 예시의 롱스커트)은 네 선지가 똑같이 공유하는 "배경"입니다.
이렇게 하면 **선호 판단은 선호 축 하나로만, TPO 판단은 위반 축 하나로만**
갈리기 때문에, 모델이 뭘 틀렸는지 깔끔하게 해석할 수 있습니다.

시나리오는 두 종류입니다:

- **Physical**: 물리적 제약이 있는 상황 (폭설, 수영장, 등산 등 32개)
- **Dress-code**: 사회적 복장 규범이 있는 상황 (장례식, 면접, 결혼식 등 28개)

## 2. 무엇이 문제였나

현재 벤치마크(문제 2,760개)를 점검하면서 여섯 가지 문제를 확인했습니다.

### 문제 ① TPO 판단이 사실상 "옷 종류"만 물어봄

위반 축의 분포를 세어보니 **garment 89% / color 9% / pattern 2%**였습니다.
즉 "상황에 안 맞는 선지"가 거의 항상 *옷 종류*가 틀린 선지였다는 뜻입니다
(갈라에 탱크톱, 수영장에 코트 같은 식).

왜 문제냐면 — 장례식 시나리오에는 "밝은 색 금지"라는 색 규범이 정의되어
있는데, 정작 색이 틀린 선지는 거의 출제되지 않았습니다. 그러면 모델이
**색·무늬 규범을 전혀 몰라도 옷 종류만 보고 TPO 만점**을 받을 수 있습니다.
리뷰어가 가장 먼저 공격할 지점입니다.

### 문제 ② "옷 종류 취향"은 한 번도 측정 안 됨

유저 프로필에는 옷 종류 취향(예: 블레이저 좋아함)도 정의돼 있는데, 선호 축은
색과 무늬만 가능하게 되어 있습니다. "3가지 취향을 정의해놓고 2가지만
측정한다"는 지적이 가능합니다.

### 문제 ③ "격식 = 규제 있음"이라는 지름길

현재 카탈로그에서 색·무늬 규제가 있는 시나리오는 **전부 격식 상황**(면접,
장례식…)이고, 캐주얼 상황은 전부 규제가 없습니다. 그래서 모델이 규범을
이해하지 못해도 **"장면이 격식이면 검정·무지를 골라라"**라는 단순 규칙만으로
점수를 딸 수 있습니다.

### 문제 ④ "밝은 색 = 오답"이라는 지름길

주황·노랑·흰색은 벤치마크 전체에서 **오답(C·D) 선지에만** 등장합니다. 모델이
"쨍한 색이 보이면 무조건 거른다"는 통계적 요령을 익히면 이득을 봅니다.

### 문제 ⑤ 문제를 더 만들고 싶어도 못 만듦

색·무늬 위반 문제를 늘리려고 해봤더니, 생성 로직의 문제가 아니라 **재료
부족**이었습니다. 색·무늬 위반 선지를 만들려면 "유저가 좋아하지도 싫어하지도
않는(=중립인) 값"이 규범의 허용 목록과 금지 목록 양쪽에 남아 있어야 하는데,
유저 취향이 어휘를 다 먹어버려서 남는 값이 없는 경우가 대부분이었습니다.
(예: 무늬 어휘는 6개뿐인데 유저 취향이 4개를 차지)

실제로 색·무늬 위반이 가능한 문제는 2,760개 중 328개가 최대치였고, 이미
310개를 쓰고 있었습니다. **생성 로직 개선으로는 +18개가 한계** — 유저 프로필과
시나리오 자체를 바꿔야 합니다.

### 문제 ⑥ 유저별 쏠림의 재발 위험

과거에 "U001 유저의 A 선지 무늬가 60개 중 59개가 스트라이프"인 쏠림을 발견해
배분 로직으로 고쳤지만, 이는 사후 처리입니다. 프로필 구조가 바뀌면 언제든
재발할 수 있어서, 생성 단계에서 원천적으로 막는 쪽이 안전합니다.

## 3. 해결의 큰 그림

세 가지를 바꿉니다. 순서대로 읽으면 서로 맞물리는 구조가 보입니다.

1. **문제 정의를 둘로 나눈다** — Physical과 Dress-code는 원래 성격이 다른
   문제임을 논문 정의 수준에서 인정한다. (→ §4)
2. **유저 프로필을 "규칙"으로 다시 만든다** — 취향을 자유롭게 뽑지 않고,
   어휘를 역할별로 나눠 정해진 몫만큼 배정한다. 그러면 "문제를 만들 재료가
   항상 남아 있음"이 수학적으로 보장된다. (→ §5)
3. **시나리오를 넓힌다** — 격식이 아니면서도 색·무늬 규칙이 있는 상황(사파리,
   야간 러닝, 무대 스태프…)을 추가해 지름길 ③④를 끊는다. (→ §6)

## 4. 변경 1: 문제 정의 이원화

**원리: 제약의 성격이 문제의 구조를 결정한다.**

| | Physical | Dress-code |
|---|---|---|
| 제약의 성격 | 물리적 (방수, 보온, 운동성) | 규범·규칙 (격식, 안전 수칙, 촬영 규칙…) |
| 제약이 걸리는 속성 | 옷 종류뿐 | 옷 종류 + 색 + 무늬 |
| 위반 축 | 옷 종류 **고정** | 제약된 속성 중에서 **돌아가며** 선택 |
| 선호 축 | 색, 무늬 | 색, 무늬, **옷 종류(신규)** |

이렇게 나누면 두 가지가 해결됩니다.

- Physical 문제가 전부 garment 위반인 것은 결함이 아니라 **정의의 귀결**이
  됩니다. ("폭설엔 패딩"이지 "폭설엔 파란색"이 아니므로.)
- Dress-code에서는 옷 종류도 선호 축이 될 수 있어 문제 ②가 해소됩니다.
  예: "블레이저를 좋아하고 롱스커트를 싫어하는 유저 + 갈라" 문제에서
  A=블레이저, B=롱스커트(둘 다 갈라에 OK), C·D=노란색(색 위반).

## 5. 변경 2: 프로필 생성 규칙 (핵심)

### 5.1 어휘를 역할별로 나눈다

옷·색·무늬의 어휘를 세 칸으로 나눕니다. 중요한 점: **이 구분은 "격식"이라는
감각이 아니라, 속성별로 "그 속성을 제약하는 시나리오들의 허용/금지 목록"에서
기계적으로 계산됩니다.** 카탈로그가 바뀌면 칸도 다시 계산됩니다.

- **ANCHOR (공통 허용 값)**: 그 속성을 제약하는 **규범 계열 시나리오 전부가
  공통으로 허용**하는 값.
  - 옷 {블레이저, 정장셔츠, 드레스} — 규범-격식 7계열(비즈니스·법정·장례·
    결혼 등 28개)의 허용 목록에 모두 포함 (S1 규칙으로 보장)
  - 색 {검정, 네이비, 회색} — 색을 제약하는 규범 시나리오 전부가 허용
  - 쓰임새: 유저마다 여기서 좋아하는 값 1개 + 싫어하는 값 1개를 배정
    → 규범 계열의 어떤 시나리오에서든 A(좋아하고 적절)·B(싫어하지만 적절)
    선지의 재료가 반드시 존재

- **RESERVE (측정 도구로 예약된 값)**: **누구의 취향에도 배정하지 않는** 값.
  예약하는 이유가 두 가지로 다릅니다:
  - *위반값 공급용*: 색 {주황, 노랑, 핑크, 흰색}(규범 시나리오들이 준보편적으로
    금지), 무늬 {레오파드, 도트}. 항상 취향-중립이므로 "취향과 무관하게
    상황에만 안 맞는" C·D 선지를 언제나 만들 수 있음
  - *허용쪽 중립 공급용*: 무늬 {체크}. 금지라서가 아니라 그 반대 —
    무늬 위반 문제에서 A·B가 입을 "허용되면서 취향 무관한 무늬"가 하나는
    남아 있어야 해서 예약 (무늬 어휘가 6개뿐이라 필요한 조치)

- **FREE (자유 값)**: 위 두 역할이 없는 나머지. 취향 다양성(페르소나) 담당.

**Physical에서는 어떻게 되나?** Physical은 색·무늬를 제약하지 않으므로 이 칸
나누기가 관여할 일이 없습니다. Physical 문제의 선호 축(색·무늬)은 유저 취향을
그대로 쓰고, 옷 종류의 중립 쌍은 아래 R4 규칙이 (Physical 포함 모든
시나리오에 대해) 보호합니다. 단 한 가지 파급: RESERVE 색 4종은 Physical에서도
취향 대상이 아닙니다 (§5.3의 트레이드오프 2).

**격식이 아닌 Dress-code(신규 시나리오)에서는?** 야간 러닝에서는 검정이
오히려 금지색이라 ANCHOR의 "공통 허용"이 성립하지 않습니다. 이런 시나리오는
**색-선호 문제를 만들지 않는다고 선언**하고, 대신 색-위반 문제를 전원
보장합니다 (ANCHOR 색 3개 중 취향에 배정되는 건 2개뿐이므로 최소 1개는 항상
중립으로 남아 위반값이 됨). 이렇게 **시나리오마다 지원하는 문제 유형을
선언하는 방식을 "호스팅 클래스"**라 부르며, 보장 명제는 "모든 시나리오가 모든
유형을"이 아니라 **"각 시나리오가 선언한 유형은 모든 유저에 대해 성립"**입니다.

그 위에서 프로필을 만들 때 세 가지 규칙만 지킵니다.

> **규칙 1 (R1, 옷)**: 모든 유저는 ANCHOR에서 좋아하는 옷 1개 + 싫어하는 옷
> 1개를 갖는다. 나머지 취향(각 2개)은 FREE에서.
>
> **규칙 2 (R2, 색)**: 색도 마찬가지 — ANCHOR 1 + FREE 2 (likes/dislikes 각각).
> 단, **RESERVE 색은 누구의 취향에도 넣지 않는다.**
>
> **규칙 3 (R3, 무늬)**: 솔리드/스트라이프 중 하나를 좋아하고 다른 하나를
> 싫어한다(유저 절반씩 교차). 플로럴은 유저 ⅓씩 좋아함/싫어함/중립. 체크·도트·
> 레오파드는 항상 중립으로 남긴다.

### 5.2 왜 이러면 되는가

- **A·B 선지가 항상 존재**: 규범 계열의 어떤 시나리오든 유저에게 "좋아하는
  적절한 옷"과 "싫어하는 적절한 옷"이 최소 1개씩 있음 (ANCHOR 규칙 덕분).
  → 문제 ②의 옷-선호 문제를 규범 계열 전체(유저×시나리오)에서 만들 수 있음.
- **C·D 선지 재료가 항상 존재**: RESERVE 값은 아무도 좋아하거나 싫어하지
  않으므로, "취향과 무관하게 상황에만 안 맞는" 위반 선지를 언제나 만들 수
  있음. → 문제 ⑤(재료 부족)가 원천 해소.
- **취향과 규범 신호가 안 섞임**: "노란 옷을 거른 게 취향 때문인지 규범 이해
  때문인지"라는 교란이 어휘 수준에서 차단됨.

기존에는 이 조건들이 "운 좋으면 성립"이었는데, 규칙 덕분에 **"항상 성립함을
증명 가능"**해집니다. 벤치마크 논문에서는 "돌려보니 되더라"보다 "이렇게 설계해서
될 수밖에 없다"가 훨씬 강한 서술입니다.

### 5.3 대가 (숨기지 않고 논문에 쓸 것)

- 무늬 취향이 사실상 솔리드 vs 스트라이프로 좁아짐 (어휘 6개 중 3개를 측정
  도구로 예약했기 때문). 근본 해결은 무늬 어휘 확장인데 이미지 수집까지
  연쇄되므로 이번에는 한계로 명시하고 future work로.
- 주황·노랑·핑크·흰색은 벤치 전체에서 "취향의 대상"이 되지 못함. 이는 실험
  통제(교란 제거)로 정면 서술.

### 5.4 시나리오 쪽의 짝 규칙

프로필 규칙이 성립하려면 시나리오도 조건을 맞춰야 합니다.

- **S1**: 규범-격식 계열 시나리오의 허용 옷 목록에 옷 ANCHOR 3종이 다 들어
  있어야 함.
  현재 9개 시나리오에 드레스가 빠져 있어 추가 필요. (아직 미반영 — §9 실행 순서 참조)
- **S2**: 색 금지 목록에는 RESERVE 색이 최소 1개 들어 있어야 함(위반 선지
  재료 보장). 예외 4건은 다른 방식으로 보장됨을 확인하고 문서화함.

## 6. 변경 3: 시나리오 확장 — "격식 아닌데 규칙 있는" 상황들

### 6.1 왜 필요한가

문제 ③을 다시 보면: 지금은 "색·무늬 규칙 있음 = 격식"이 100% 일치합니다.
이 일치를 깨려면 **캐주얼이면서 규칙이 있는 상황**이 필요합니다. 실제로
존재합니다 — 근거가 "예의"가 아니라 "기능"일 뿐입니다.

### 6.2 추가된 4개 아키타입, 12개 시나리오 (구현 완료)

| 아키타입 | 시나리오 | 규칙과 근거 | 특별한 역할 |
|---|---|---|---|
| 야간 시인성 | 야간 국도 러닝, 야간 자전거 퇴근, 새벽 갓길 봉사 | 어두운 색 금지(차에 안 보임) — **밝은 색이 정답** | 문제 ④ 해결: 주황·노랑·흰색이 처음으로 정답 선지에 등장 |
| 필드 위장 | 사파리, 페인트볼, 야생동물 촬영 | 쨍한 색·화려한 무늬 금지(동물 자극/은폐) | 체크무늬(플란넬)가 허용이라 무늬 위반 문제도 생성 가능 |
| 무대·방송 | 백스테이지 스태프(올블랙), 크로마키 촬영, TV 인터뷰 | 업계 표준 규칙 | TV 인터뷰는 "기능적 규칙 + 격식 옷"의 유일한 조합 |
| 클럽 규정 | 윔블던식 테니스(올화이트), 요트클럽, 골프클럽 | 성문화된 클럽 규칙 | "규범이지만 캐주얼" — 격식 지름길을 안쪽에서도 차단 |

### 6.3 "사람도 모르는 규칙 아닌가?" 문제

플라이낚시 복장 규칙 같은 건 일반인이 모릅니다. 그런 문제를 내면 모델이
틀려도 "추론 실패"인지 "지식 부재"인지 구분이 안 되고, 인간 정답률도
떨어집니다. 대응:

- **상식 수준 규칙**(야간 시인성, 장례식)은 쿼리에 규칙을 안 써도 됨 (implicit)
- **틈새 규칙**(크로마키, 촬영 하이드)은 쿼리에 규칙을 명시 (explicit:
  "가이드가 어스톤만 입으라고 했어요") → 지식 문제가 "지시 적용 + 취향 결합"
  문제로 바뀜
- 최종적으로 **전 시나리오 인간 정답률을 측정**해서 기준 미달이면 implicit
  금지 또는 제외

### 6.4 보수적 검수 — 반례 봉쇄 (구현 완료)

"이 옷이 부적절하다"고 주장하는 목록(incompatible)은 반례 하나로 무너지므로
전수 검수했고, 다음을 수정했습니다.

| 발견된 반례 | 수정 |
|---|---|
| 갈라에서 핑크 이브닝드레스는 정상 (여성복 기준) | 초격식 시나리오의 색 위반은 수트 계열 옷(셔츠·블레이저·슬랙스)으로만 구현하도록 스코프 지정 |
| 핑크 셔츠는 흔한 비즈니스 복장 | 비즈니스 4종에서 핑크를 금지 목록에서 제거 |
| 빨간 바지는 요트클럽의 상징(Nantucket red) | 요트 시나리오에서 빨강·핑크 제거 |
| 다크그린 정장은 장례식에서 통용 가능 | 장례 4종에서 초록 제거 |
| 도트 원피스는 데이트 복장의 클래식 | 갤러리·데이트에서 도트 제거 |
| 그린스크린 앞에서 파란 옷은 문제없음 | "그린+블루 겸용 스튜디오"로 시나리오 재정의 |

수정 후 재검증 결과 통계 분포는 변화 없음 — 방어력만 올라가고 잃은 것 없음.

## 7. 효과: 전/후 비교 (시뮬레이션 검증)

새 프로필 규칙 + 새 카탈로그로 시뮬레이션한 결과입니다.

| 지표 | 현재 | 재설계 후 |
|---|---|---|
| 총 문제 수 (상한) | 2,760 | **4,736** |
| 위반 축: garment | 89% | 67% |
| 위반 축: color | 9% (248개) | **23% (1,107개)** |
| 위반 축: pattern | 2% (62개) | **10% (466개)** |
| 옷-선호(garment-active) 문제 | 0 | 576 (전 유저 균등 24개씩) |
| "밝은 색이 정답" 문제 | 0 | 84 |

**garment가 여전히 많은 이유** (미리 답해두는 질문):
① Physical 1,536개는 정의상 garment ② 옷 종류는 모든 시나리오가 제약하는
유일한 속성이라 기본 판이 됨 ③ 현실의 TPO 상식 자체가 "장례식에 반바지
금지"처럼 옷 종류가 1차 규범임. 개수를 억지로 맞추는 대신 **평가 지표를 축별
평균(macro-average)으로** 보고하면 개수 불균형이 점수에 영향을 주지 않습니다.

## 8. 평가 방법 보강 (데이터와 별개로 필요한 것)

1. **축별 점수 분리 보고 + macro 평균** — "garment만 잘해도 고득점" 차단
2. **B vs C 순위 분석** — 지금은 정답 A가 모든 면에서 우월해서 "둘 다 만족하는
   걸 찾는 능력"만 측정됨. B(규범만 충족) vs C(취향만 충족) 중 뭘 더 높게
   평가하는지를 보면 모델의 우선순위 판단까지 측정 가능 — 데이터 재생성 없이
   추가되는 공짜 지표
3. **인간 정답률 측정** — 층화 샘플 200~300문항. "인간도 못 푸는 벤치" 공격 차단
4. **explicit vs implicit 분리 분석** — 지식과 적용을 구분
5. **같은 쿼리에서 나온 쌍둥이 문제는 묶어서 통계 처리** (클러스터 부트스트랩)
   — 문제 수를 늘린 대가로 생기는 비독립성 처리
6. **검산 항목**: 선지 위치 셔플 확인, 배경 속성과 정답의 상관 없음 확인
7. **시드 3개로 재생성해 모델 순위가 안정적인지 확인**

## 9. 실행 순서

```
[완료] 시나리오 카탈로그 v2 (신규 12종 + 검수 패치)
[완료] 규칙 검증 시뮬레이션

1. 프로필 생성기에 규칙 R1~R3 + 재추첨 로직 구현
2. 카탈로그에 S1 반영 (격식 7종에 드레스 추가; 재생성 직전에 적용해
   기존 데이터 재현성을 그대로 보존)
3. 쿼리 생성기 확장: 옷-선호 축 지원, 틈새 시나리오는 explicit 쿼리만
4. 선지 생성기 확장: 쿼리당 여러 위반 축 판 생성, 초격식 색-스코프 반영,
   유저별 균형 카운터를 새 구조에 맞게 재실행
5. 전체 재생성 (시드 3개)
6. 재검증: 커버리지 / 유저별 균형 / 혼동쌍 비율 / 위반 축 분포
   → 기존 지표가 하나라도 나빠지면 임시 패치가 아니라 규칙을 고쳐서 재생성
7. 이미지 수집: 종교 시나리오는 노출 없는 스타일 필터 적용,
   신규 시나리오(형광 러닝복, 사파리 셔츠 등)의 검색 가능성 사전 확인
8. 인간 검증 → 기준 미달 시나리오 조정 → 벤치 확정
```

## 10. 검토자에게: 결정이 필요한 것들

1. **문제 수 4,736을 다 쓸 것인가** — 이미지 수집 예산과 직결. 줄인다면
   같은 쿼리의 쌍둥이 판(축 비교용)은 보존하고 garment 기본 판에서 덜어내는 방식.
2. **무늬 어휘 확장 여부** — 무늬 취향 다양성 문제의 근본 해결이지만 비용이
   큼. 이번 제출은 한계 명시로 가는 것을 권고.
3. **신규 시나리오의 이미지 확보 가능성** — 아직 아무도 확인 안 한 유일한
   외부 의존성. 7단계 전에 소규모 검색 테스트 권장.
4. **기존 2,760문제의 처리** — 재설계본과 별도 버전으로 보관, 비교 실험용으로
   유지 권장.
